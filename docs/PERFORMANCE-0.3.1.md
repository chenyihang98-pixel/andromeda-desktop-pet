# 0.3.1 资源、比例与代码审查

2026-10-22。本轮针对实际热路径、生命周期和可复现缺陷；不将其称为完整 54 项路线图已经完成。当前源码与本地构建是 0.3.1 开发版，公开下载仍为 v0.2.0。

## 测量口径

桌面使用 `scripts/resource-probe.cjs` 启动真实 Electron 44.5.1，在独立 `qa/resource-profile-*` 目录创建合成资料，默认关闭联网、声音、移动和注视，静置模式固定为 still。Windows 10 x64，Intel i7-10875H，16 逻辑处理器；当前实际显示器 1280×720 DIP、工作区 1280×680 DIP、150% 系统缩放。

每个场景先稳定 2 秒，再采样 20 秒。CPU 是 Electron 各进程累计 CPU 时间增量之和除以墙钟时间，**一个核心用满为 100%**，不是整机任务管理器的归一化百分比。内存是各进程 private bytes 总和；working set 也记录，但其共享页面会重复计算。不开强制 GC，不把一次短样本当作所有机器保证。Windows API 不提供真实空闲唤醒次数，本报告只统计应用 IPC、画布重绘、DOM 变更和存档 rename 次数。

优化前静置基线是 `8617c26` 工作树；互动基线由上一轮验证过的 0.3.0 ASAR 运行，其运行时代码与基线一致。大存档包含 160 条记忆、180 条待办、80 条任务，JSON 共 1,291,021 字节，全部为合成文字。互动每 2.5 秒触发挥手；漫游仅在该隔离测试中显式开启。公开状态读取不应随私人记录数量成倍变慢。

第一次优化后 Studio 静置样本收到非计划互动事件，因此不用于静置比较。最终结果使用比例修复后的重新采样；探针会标注非预期活动，并让自有测试窗口在采样期间忽略指针，避免误把点击计作空闲开销。原始 JSON 留在忽略目录 `qa/`。

## 桌面实测

同机每场景 20 秒，CPU 按单核心 100% 口径，内存为进程 private bytes 合计。箭头左侧是 0.3.0 基线，右侧是本轮结果；不是跨机器保证。

| 场景 | CPU %：前 → 后 | 私有内存 MiB：前 → 后 | 存档写入：前 → 后 |
|---|---:|---:|---:|
| 经典静置 | 0.440 → 0.201 | 201.9 → 192.4 | 1 → 0 |
| 陪伴面板静置 | 1.428 → 0.344 | 242.7 → 242.3 | 1 → 0 |
| Studio 静置 | 0.791 → 0.133 | 188.1 → 183.0 | 1 → 0 |
| 专注运行、面板今天页 | 1.698 → 0.372 | 263.6 → 244.3 | 1 → 1 |
| 手动隐藏 | 0.274 → 0.072 | 197.7 → 187.4 | 2 → 0 |
| 合成大存档挥手 | 2.528 → 0.788 | 247.0 → 203.8 | 1 → 0 |
| 合成大存档漫游 | 16.518 → 11.569 | 281.1 → 209.0 | 2 → 0 |

经典、面板、Studio 静置及隐藏场景，本轮重复 Canvas draw、DOM mutation、状态 IPC 和存档写入均为 0；各样本没有非计划互动事件。Studio 基线有 19 次绘制和 19 次公共广播，隐藏基线有 20 次绘制和 20 次公共广播。专注场景保留 1 次保存检查点和 1 次面板广播；本地倒计时仅在可见任务页刷新，不把它当成无成本。

漫游仍需移动原生透明窗口并绘制动作，CPU 高于静置；前后事件数为 11 / 10、绘制数为 47 / 41，随机动作时序并非完全相同。这组 CPU 是参考样本，不能仅凭它保证固定百分比降幅。挥手为相同定时触发、同样 11 次绘制；私有资料不再进入每次移动的公共状态读取。内存短样本受 GC/操作系统影响，面板静置内存基本没有下降；Electron 运行时仍是主要固定成本。

## 网页实测

Chromium 本地生产构建，普通样本 1.2 秒、展示区样本 2.2 秒。测量的是回调、绘制与网络响应正文，不是 CPU、功耗或显存；hidden 通过可重复的 visibility 事件注入。

| 场景 | 前 → 后 |
|---|---:|
| SDK 200 次远处鼠标移动：绘制 / 边界读取 | 200 / 200 → 0 / 1 |
| SDK 导出后立即销毁：残留 Blob URL | 1 → 0 |
| 首页隐藏展示：绘制 / 待执行计时器 | 13 / 3 → 0 / 0 |
| 角色页隐藏展示：绘制 / 待执行计时器 | 25 / 6 → 0 / 0 |
| 首页 / 角色页普通 3D：1.2 秒 RAF 次数 | 175 / 176 → 30 / 29 |
| 首页 / 角色页减动 3D：1.2 秒 RAF 次数 | 176 / 172 → 0 / 0 |
| 首页完整冷访问正文 bytes | 2,541,892 → 2,549,732 |
| 角色页完整冷访问正文 bytes | 2,428,740 → 2,436,580 |
| 网站主 JS bytes | 20,928 → 24,136 |

SDK 静置/隐藏原本就没有连续 RAF，这项没有额外改善。正常 3D 每帧使用延时调度，上限 30 fps；减少动态切换时首页/角色页仍进行 3 / 6 次必要静态绘制，之后无持续刷新，手动拖转有效。

销毁后站宠及展示组件的 timer、RAF、Blob 和 Canvas 清零；不是整页所有监听清零。SDK demo 留下 7 个宿主监听和 1 个探针监听，真实站点留下 26 个普通宿主监听；40 次面板重建没有残留脱离 DOM 的元素监听。WebGL 的 geometry、material、texture、环境渲染目标、controls 和 renderer 显式释放，不等于已测得 OS 显存归零。

新增生命周期处理使完整访问增加 7,840 字节、主 JS 增加 3,208 字节，未宣称网络体积下降。网站仍只请求一次 585,898 字节经典图集，可选 Studio 默认零请求。SDK 演示使用较大的桌面原图集，其正文 3,345,173 → 3,346,919 字节，不能套用网站的图集数字。

## 已落实的优化

- 领域引擎提供下一截止时间、轻量公共状态和持久变更修订号。空闲取消 1 Hz 全量复制/广播与每 15 秒无变化写盘；专注仍每 15 秒保存检查点，截止时间由宿主处理，只有可见任务页更新本地倒计时。静音提醒仍立即保存，睡眠恢复重新校时；保存失败最多每 30 秒重试。
- 移动循环不再遍历私人记忆和任务；轻抛未开始或已落稳时不轮询，跟随静止时降低采样频率。隐藏窗口不再接收无变化广播。行为队列按动作结束/冷却截止唤醒，替代 100 ms 轮询。
- 经典桌宠启动不加载 2,652,111 字节的可选 Studio 图；面板图鉴按需加载。重复姿态、同方向注视和相同减动设置不再重画。角色动作解析只在挂载时完整校验一次，外部通用校验 API 保留。
- 面板列表按 ID 保留节点和编辑草稿，修复同文条目编辑错对象、无关更新丢焦点；流式文字按绘制帧合并，取消后的迟到消息不复活。截图移除时清除图片引用，声音结束/取消时释放音频上下文。
- 网页同帧不重画，注视复用边界测量；销毁即时释放导出 Blob URL、定时器、监听器和加载资源。站点独立动作展示在隐藏时停止，3D 正常动画上限 30 fps，减少动态时改为交互/尺寸变化触发绘制，销毁释放模型、纹理、环境和 WebGL 上下文。
- 删除网站不再导入的旧向导实现、旧提示和样式，以及旧动画辅助函数；删除领域分发中已经被提前返回覆盖的分支。旧向导三文件共 30,235 字节是死源码，原本已被构建器排除，**不能算成用户下载减少 30 KB**。公开 API 按契约保留。
- 修复角色包紧凑/美化 JSON 大小标准不一致导致“导出成功却导入失败”；按最终 UTF-8 清单字节统一 64 KiB 边界。备份/宿主/面板统一 4 MiB，最长合法 Unicode 字段及全部集合满载为 2,715,069 字节，未来到期通知后仍可往返。录音 IPC 按二进制大小计数，避免展开成逐字节 JSON。
- Windows 包默认改为 normal 压缩，减少构建 CPU 时间；运行时代码和素材不因压缩档改变。两工程本轮 `npm audit` 都返回 0 个已知漏洞；这不是无漏洞证明。

## 人物比例修复

桌面 Studio 原来把 313.5×418 的单格直接拉到 384×416，横向相对放大约 23.08%。现按等比 contain 绘为 312×416，左右各留 36 像素，底部对齐。原图不重采样、不修改；原版 192×208、自定义长宽比例和 Studio 各自保持真实比例。

另一个缺陷是小工作区中分别压缩窗口宽高：例如 1280×720、200% 系统缩放、48 DIP 任务栏，工作区为 640×312 DIP，200% 桌宠原需 384×416 DIP。旧停靠展开会变成 384×312，人物被横向拉宽约 33.33%；自由窗口则可能超出底部。现在窗口整体等比适配，保留主人设置的缩放意图，移回较大显示器恢复。把手的紧凑窗口独立处理，DPI 不重复乘到 DIP。

画布 CSS 也保留固有比例并底部居中，防止窗口管理器强制不同宽高时拉伸；点击/拖动继续以真实画布矩形换算。网页原角色绘制已有等比缩放，另修复面板按 600px 估高而实际可达 650px，导致 1024×768 下超出底部的问题。

桌面浏览器矩阵：1280×720、1366×768、1920×1080、2560×1440、3840×2160、3440×1440、1080×1920；DPR 1/1.25/1.5/2；桌宠缩放 75%/125%/200%；经典、Studio、自定义三类共 252 场景，加 12 组非标准窗口。验证画布边界、源/目标横纵缩放一致及合成自定义角色像素比例。

窗口层另有 1,440 组纯几何、240 组主进程适配模拟以及 126 个合法缩放值核对，覆盖任务栏、负坐标、跨屏抓取点、缩小/恢复、显示器移除与重置。当前物理屏幕的五档缩放也由真实 Electron 验证。设置界面保留原缩放百分比，并明确提示工作区导致的临时等比缩小。

网页矩阵：390×844、844×390、1024×768、1366×768、1920×1080、2560×1440、3840×2160；四档 DPR、两种外观，共 56 场景、312 断言。按实际 alpha 形状与源素材独立核对比例。以上是浏览器模拟和纯几何验证；当前只有一块真实显示器，混合 DPI 多屏热插拔仍待物理设备验收。新 Studio 图本身仍有透明边缘/角色细节待美术修整，比例修复不代表连续动画制作完成。

## 复现

```powershell
npm run verify
npm run test:ui
npm run test:proportions
npm run profile:resources -- --label=current --seconds=20
npm run profile:resources -- --label=current-actions --seconds=20 --actions
node web/measure-resources.mjs current ../site-project/dist
```

浏览器资源脚本的 hidden 使用可重复的 visibility 事件注入，测的是计时器/绘制/销毁行为，不是物理后台功耗。截图和逐条报告在 `qa/`；最终分层结果与构建身份见 [验证记录](VALIDATION-0.3.1.md)。
