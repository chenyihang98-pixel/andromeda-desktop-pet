## 已修复问题

1. **原生把手尺寸超出工作区。** 未修复配置请求 14×64 DIP 时，Windows 实际返回 30×64；请求 64×14 时返回 64×36。右边原请求 x=1906，实际右界达到 1936（超过 1920）；底边原请求 y=1018，实际下界达到 1054（超过 1032）。最小尺寸和 `thickFrame` 配置探针未能解除本机限制。因此在设置边缘窗口后读取真实尺寸，按指定显示器的工作区重新贴边、约束位置；把手随实际窗口填充。目标大小仍为 14×64 / 64×14，原生系统可扩大它。
2. **菜单没有立即终止拖动。** 原生菜单打开时取消主进程拖动，并阻止菜单未关闭期间的新拖动；渲染器同时释放捕获。迟到的松手不提交停靠。
3. **其他指针结束当前拖动。** 拖动现在绑定发起它的 `pointerId`，仅接受它的移动、释放和取消；状态清理先于释放捕获，防止重复结束。
4. **临时小尺寸遗留。** 极小工作区令停靠窗口缩小后，解除停靠按当前设置的 `petSize` 恢复尺寸。
5. **Windows 检出无法运行完整回归。** 渲染器测试的导入识别兼容 LF/CRLF，并保留导入变更检查；浏览器测试查找已安装的浏览器，支持 `CHROMIUM_PATH`，不关闭沙箱。

尺寸修复依据本机观测。Electron 的参数含义可查 [窗口选项](https://www.electronjs.org/docs/latest/api/structures/base-window-options)；固定版本 [原生窗口实现](https://github.com/electron/electron/blob/v44.5.1/shell/browser/native_window_views.cc) 也显示透明窗口禁用 thick frame。没有新增原生依赖或更改平台支持范围。

## 原生几何探针与剩余矩阵

`scripts/windows-smoke.cjs` 用真实 Electron `BrowserWindow` 在当前 Windows 显示器上检查四个工作区边缘的完整尺寸、收起尺寸与恢复尺寸。它使用仓库 `qa/` 内隔离的配置目录，不加载正式桌宠配置、不截屏、不读取其他窗口标题或内容、不接收鼠标输入，正常和失败路径均关闭探针进程。

运行：

```powershell
node node_modules/electron/install.js
.\node_modules\.bin\electron.cmd scripts/windows-smoke.cjs
```

结构化输出在 `qa/windows-smoke.json`，包含 OS、运行时、显示器 DIP/DPI、请求与实际边界、源码身份和检查结果。这是独立原生几何探针，**不是**完整发行程序的鼠标路由、透明合成、托盘或电源事件验收。

保存的证据：[修复前报告](validation/windows-geometry-before.json)、[修复后报告](validation/windows-geometry-after.json)、[本地构建源文件 SHA-256](validation/windows-source-sha256.txt)。报告中的 `source.commit` 和 `workingTreeDirty` 保留测试发生时的基线与未提交状态，不是后续提交的身份。SHA-256 对应当时实际读取和打包的 Windows 工作区字节（可能含 CRLF），不等同于 Git 规范化换行后的 blob 哈希；后续可结合提交历史核对内容。
